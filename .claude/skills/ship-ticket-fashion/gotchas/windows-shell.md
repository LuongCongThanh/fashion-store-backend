# Gotchas: Windows shell

- **`python3` missing or opens Microsoft Store**: cause: Python for Windows installs `python`/`py`; `python3` is a Store stub. Fix: replace `python3` in the skill's sample commands with `python`. (sample commands switched to `python3` for Linux)
- **Every Bash/PowerShell call blocked with `PreToolUse hook error … Python was not found`**: cause: a hook in `.claude/settings.json` called `python3` directly and hit the Store stub. Fix: hooks go through `.claude/hooks/run_py.sh` (picks `python3` / `python` / `py`); to type `python3` like Linux, create `python3.exe` next to the real `python.exe` (ahead of `WindowsApps` in PATH). Recreate it after upgrading Python into a new folder. (backoffice-login)
- **`gh pr create -F <file>` says "flag needs an argument"**: cause: the scratchpad path (`C:/Users/SMD415~2/…`, user name with a space) got wrapped or split when pasted. Fix: write the PR body to `.git/PR_BODY.md` and pass `-F .git/PR_BODY.md`. (PR #12)
- **Arguments starting with `/` become `C:/Program Files/Git/...`**: cause: Git Bash path conversion. Fix: prefix the command with `MSYS_NO_PATHCONV=1`. (project saafehouse-fe)
- **PowerShell `Get-Content` fails on paths with `[` `]`**: cause: `[ ]` are wildcards. Fix: `-LiteralPath`, or use the Bash tool. (project saafehouse-fe)
- **`UnicodeEncodeError`/`UnicodeDecodeError` when Python prints Vietnamese to a pipe** (`python -c … | …`, `uv run lint-imports > file`, tests calling `subprocess.run(..., text=True)` on `manage.py`): cause: redirected output uses the machine's ANSI code page (e.g. `cp1252`). Fix: set `PYTHONUTF8=1` before the command or in the subprocess `env`; `make`, `run_logged.py` and the `lint-imports` hook already set it. (backend-bootstrap/21, 23)
- **In a new worktree, `make test` says `ImportError: Thiếu hoặc sai biến môi trường` and mypy says `Error constructing plugin instance of NewSemanalDjangoPlugin`**: cause: `.env` does not follow into the worktree (it is gitignored). Fix: `cp <main repo>/.env <worktree>/.env` without reading it. (backend-bootstrap/23)
- **LF files turn CRLF after a script edits them** (git warns "CRLF will be replaced by LF"): cause: `pathlib.Path.write_text` turns `\n` into `\r\n` on Windows. Fix: use the Edit tool, or `write_text(..., newline="\n")`. (backend-bootstrap/21)
